# AGENTS.md

This file is a short operating guide for future developers and coding agents working in `vela-cli`.

## 1. Project Purpose

- `vela-cli` is a Node.js CLI for inspecting and updating Vela resources.
- The current command shape follows `kubectl` style: `vela-cli <verb> <resource>`.
- The tool supports read-only queries, browser capture, and controlled policy updates.
- The main CLI entrypoint is `src/cli.js`; API access lives in `src/api.js`.

## 2. Directory Map

- `src/cli.js`: command registration, output rendering, completion, policy edit/apply flow.
- `src/api.js`: login, authenticated requests, one-time re-login on `401/403`.
- `src/capture.js`: Playwright-based capture flow with read-only safety checks.
- `src/cli.cmd`: Windows wrapper for launching the CLI.
- `docs/INSTALL.md`: install and distribution notes.
- `artifacts/`: capture output; usually do not edit by hand.
- `dist/`: packed artifacts; usually generated by packaging steps.

## 3. Runtime Notes

- Use Node.js 20+.
- Install dependencies with `npm install`.
- The codebase uses CommonJS. Do not mix in ESM without a clear reason.
- There is currently no dedicated test, lint, or formatter script in `package.json`.

## 4. Common Commands

```bash
npm install
npm link
node ./src/cli.js --help
node ./src/cli.js get apps
node ./src/cli.js get app <name>
node ./src/cli.js get policy <app> <policy> -o yaml
node ./src/cli.js edit policy <app> <policy>
node ./src/cli.js apply -f ./policy.yaml --app <app>
npm run capture -- --headed
npm run endpoints
npm pack
```

On Windows PowerShell prefer:

```powershell
node .\src\cli.js get apps
.\src\cli.cmd get apps
vela-cli get apps
```

## 5. Environment Variables

- `VELA_TOKEN`: use a bearer token directly when present.
- `VELA_USERNAME` / `VELA_PASSWORD`: used for login when token is absent.
- `VELA_BASE_URL` / `VELA_LOGIN_PATH`: override default endpoint settings.
- `VELA_EDITOR`: preferred editor for `edit policy`.

Never commit real usernames, passwords, or tokens.

## 6. Output Stability

- Query commands usually support `table`, `json`, and `yaml`.
- Keep JSON/YAML output stable for script users.
- Prefer additive changes over breaking key renames.
- Error messages should stay direct and actionable.

## 7. If You Change CLI Commands

When adding, removing, or renaming commands, usually check all of:

- `TOP_LEVEL_COMMANDS`
- `SUBCOMMANDS`
- `COMMAND_OPTIONS`
- the matching `program.command(...)` or subcommand registration
- README examples
- completion behavior

If you change only the command registration and not the completion tables, completion will drift.

## 8. If You Change API Behavior

- `VelaClient.request()` currently retries once after re-login on `401/403`.
- Keep that behavior unless token lifecycle rules have intentionally changed.
- `getJson()` and `putJson()` throw on non-2xx responses; keep new helpers consistent.
- If auth headers, base URL, or login path change, re-check environment override behavior too.

## 9. Write Safety Rules

- The main mutating entrypoints are `edit policy` and `apply -f`.
- `apply` currently updates existing policies only; it does not create new ones.
- When a policy really changes, the CLI writes a local backup before sending `PUT`.
- Preserve the "backup first, update second" order.

Do not:

- turn read commands into implicit write operations
- add mutating requests to capture or completion flows

## 10. Capture Module Rules

- `src/capture.js` is intended for read-only capture.
- It currently allows `GET`, `HEAD`, `OPTIONS`, plus login `POST`.
- Expanding allowed methods requires an explicit safety review.
- Treat `artifacts/` as generated output, not curated source data.

## 11. Documentation Priority

If docs and code disagree, prefer this order:

1. `src/cli.js`
2. `README.md`
3. `docs/INSTALL.md`

Reason: `docs/INSTALL.md` may still contain older command examples.

## 12. Minimum Smoke Checks

There is no automated test suite yet, so run at least:

```bash
node ./src/cli.js --help
node ./src/cli.js completion powershell
node ./src/cli.js get apps --json
node ./src/cli.js get system-info -o yaml
```

If you changed policy logic, also run:

```bash
node ./src/cli.js get policy <app> <policy> -o yaml
node ./src/cli.js apply -f <file> --app <app>
```

If you changed capture logic, also run:

```bash
npm run capture -- --headed
npm run endpoints
```

## 13. Change Hygiene

- Keep changes focused; avoid unrelated cleanup in the same patch.
- Do not hand-edit `dist/` unless the task is packaging or release validation.
- Do not hand-edit old `artifacts/` results to fake verification.
- Keep user-facing command names aligned with the existing `kubectl` style.
- When behavior changes, update `README.md` in the same round when possible.

## 14. Current High-Value Facts

- `src/cli.js` is large, so search for command registration, completion, and handler code before editing.
- This repo currently relies more on manual smoke checks than on automated tests.
- The biggest risk is not code complexity; it is accidentally sending write requests.
- After changing external behavior, try to bring code, README, and install docs back into sync.
